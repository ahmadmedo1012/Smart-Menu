# Round79 — المرحلة E: مصادر خارجية مفتوحة المصدر كمرجع جودة

**القاعدة الملزمة (من الخطة):** استخلاص مبادئ معمارية/تفاعلية فقط — **ليس نسخ كود أو تصميم بصري حرفي**. هوية Smart Link (العربية-أولاً، RTL الكامل، لوحة المطبخ الدافئة basil/saffron/ember/espresso، واقع الدفع الليبي المحلي) تبقى مميزة في كل استلهام.

**ترتيب الالتزام:** ui-ux-pro-max أولاً (المرجع الأول الإلزامي قبل أي بحث خارجي) ثم المراجع الخارجية.

---

## 1) المرجع الأول: ui-ux-pro-max (شُغِّل فعليًا — search.py)

| المبدأ المستخلص | حالة Smart Menu (بأدلة الكود/المراحل) |
|---|---|
| صفحة أسعار: **ميّز الخطة الموصى بها** (pre-select/highlight) | ✅ مطبق: شارة "الأكثر شعبية" على الخطة Basic (`pricing/page.tsx:48` بتدرّج ember→saffron — بلون العلامة لا بألوان外援) |
| صفحة أسعار: **جدول مقارنة** الميزات | ✅ مطبق: PlanComparisonTable قابل الطي "قارن n بالتفصيل" (محسّن للموبايل — اسحب أفقيًا) |
| حالة تحميل: **skeleton/spinner، لا واجهة مجمّدة** | ✅ مطبق على نطاق واسع: 40 ملفًا فيها Skeleton/animate-pulse/Loader2 + loading.tsx على مستوى المسار بعجلة دوارة + "جاري التحميل..." |
| رسالة خطأ: **aria-live/role=alert لا بصريًا فقط** | ✅ مُحكّم في المرحلة C: axe صفر قواعد جديدة عبر 48 تشغيلة (صوابط حقل المبلغ البنكي useId+htmlFor أُصلحت) + premiumToast للتوست |
| إرسال: **loading → success/error دائمًا** | ✅ مطبق: PaymentDialog يمرّ form→waiting(شارة صادقة+استقصاء)→approved/rejected — وأُزيل في C عدّاد كان يوحي بنجاح تلقائي كاذب |
| تقدّم: **"خطوة 2 من 4"** | ✅ مطبق: StepIndicator بأربع خطوات مرقّمة معنونة (اختر الخطة/بيانات المنيو/بيانات الدخول/المراجعة) |
| حرية المستخدم: **زر رجوع/تخطي** في المعالجات | ✅ مطبق: زر "رجوع" يعيد خطوة (account→menu, review→account) بسهم RTL صحيح |
| استقرار التخطيط: **احجز مساحة المحتوى غير المتزامن** | ✅ مطبق جزئيًا: أبعاد محفوظة للبطاقات/الصور؛ رحلة C أكدت صفر تجاوز أفقي في 6 خلايا × 8 صفحات |

**خلاصة المرجع الأول:** حلول Smart Menu الحالية **متوافقة** مع مبادئ الكشف الآلي — لم يظهر أي مبدأ High-severity مخالف. أهم ما أكده البحث: أنماط الحالة (loading/error/feedback) التي أصلحتها المرحلة C هي بالضبط ما تصنفه الأداة High-severity.

## 2) المراجع الخارجية المدروسة (مشاريع مفتوحة المصدر ناضجة)

### 2.1 Cal.com (جدولة مفتوحة المصدر — بنية الأسعار والترقية)
**المصدر:** cal.com/pricing + مدونة الخطط الرسمية (cal.com/blog/cal-com-plans-explained)
- **المبدأ المستخلص:** سرد تصاعدي للخطط يخاطب "مرحلة النمو" (مجاني قوي → تعاون → حوكمة)، مع شفافية ميزات كل مستوى، وترقية من داخل المنتج لا بالبريد.
- **كيف يخدم Smart Link:** هيكلها الثنائي (مجاني بسخاء: منيو+10 أصناف+100 طلب / مدفوعة 29 د.ل) يحكي نفس السرد ببساطة سوق واحدة. **لم نستعر** بنية 4 مستويات (Free/Teams/Org/Enterprise) — سوق ليبيا/المطاعم الصغيرة لا يحتملها؛ البساطة ميزة تحويل هنا.
- **الفجوة الموثقة (لاحقًا):** لا قسم FAQ في /pricing — Cal.com ومنافسوه يعالجون الاعتراضات بـ FAQ. مرشّح لجولة قادمة (محتوى تسويقي، ليس عيبًا هندسيًا).

### 2.2 QR Menu (github.com/softenrj/qr-menu) — نطاق مباشر
**المصدر:** README الرسمي (Next.js + TS + Tailwind + MongoDB + Razorpay)
- **المبادئ المستخلصة:** ① QR لكل **طاولة** (طلب بلا توقف من الجلوس) ② تكامل دفع إلكتروني (Razorpay) ③ تحليلات فورية بـ Recharts ④ بانى منيو مرئي بالسحب والإفلات.
- **ما ينطبق وما لا ينطبق على Smart Link:**
  - ✅ **مضمن فعليًا:** تحليلات المالك (KPI + مخططات المرحلة H)، إدارة منيو كاملة، توليد QR فوري.
  - ⛔ **مُستبعد بقرار موثق:** الدفع الإلكتروني المدمج — Razorpay/Stripe غير متاحين في ليبيا؛ حوار الدفع المحلي (ليبيانا/مدار/تحويل بنكي + موافقة أدمن) هو **التصميم الصحيح للسوق** لا نقصًا.
  - 📋 **فجوة موثقة:** QR لكل طاولة (حاليًا QR واحد لكل مطعم) — تعزيز مباشر لتجربة الطلب؛ مرشّح جولة قادمة (يحتاج نموذج Table + تعديل الطلب).
- **الهوية محفوظة:** واجهة العميل عندنا RTL عربية كاملة بلوحة مطبخ دافئة — مشروع المرجع LTR إنجليزي بلوحة افتراضية؛ التشابه وظيفي فقط.

### 2.3 MenuQR (github.com/dustinwloring1988/menuqr) — نطاق مباشر
**المصدر:** README الرسمي (Next.js 14)
- **المبادئ المستخلصة:** ① **تخطيطات منيو متعددة** (Grid/List/Compact) ② معلومات مسببات الحساسية والتغذية ③ جداول توفر مجدولة ④ تحليلات مسح QR (جهاز/ساعة ذروة/أصناف شائعة) ⑤ نطاق فرعي مخصص لكل مطعم.
- **ما ينطبق وما لا ينطبق:**
  - ✅ **مضمن فعليًا:** شارات الحساسية والنظام الغذائي (basil/حار — من توكِنات المرحلة B)، توفر الأصناف (مفتاح Switch بمسمّى a11y أُصلح في C)، slug مخصص لكل مطعم (`/menu/[slug]`).
  - 📋 **فجوة موثقة:** تحليلات مسح QR منفصلة عن مشاهدات المنيو + جدولة توفر زمنية — مرشّحات جولة بيانات لاحقة.
  - ⛔ **مُستبعد:** تعدد التخطيطات في هذه الجولة — القسم السينمائي (H) + الشبكة الحالية يستوفيان التنوع بميزانية تعقيد معقولة؛ إضافة تخطيطات = مضاعفة كل بوابات a11y/RTL لكل تخطيط.
- **الهوية محفوظة:** بدائلنا للتخطيط تخدم نفس الغرض (تنوع إدراكي) عبر قسم سينمائي واحد مميز بدل ثلاث شبكات متشابهة.

### 2.4 Vercel Geist + Next.js Commerce (حالات الواجهة)
**المصدر:** vercel.com/geist/empty-state + مدونة Next.js Commerce 2.0
- **المبدأ المستخلص:** الحالة الفارغة "تُصمَّم لمنع الالتباس" (Geist)؛ وعند التحويل: أبقِ محملًا حتى يكتمل عرض الوجهة (قضية معروفة: انهيار لحظي لمحتوى فارغ أثناء redirect).
- **التطبيق عندنا:** حالات فارغة معنونة في 5+ مواضع مالك/أدمن (orders/owner/loyalty/charts)؛ تحويل "الانتقال إلى لوحة التحكم" بعد الموافقة يمر عبر حالة approved واضحة قبل التحويل (لا وميض فارغ) — رحلة C أكدت صفر أخطاء صفحات في كل المسار.
- **إثراء مباشر من C:** شرط Geist "المحمل حتى اكتمال التحويل" هو حرفيًا ما تحقق عند إصلاح عامل الخدمة (البيانات القديمة بعد POST كانت نقيضه الدلالي).

## 4) ضمانة عدم انتحال تصميم محمي

كل ما دُرس **مبادئ تفاعلية معلنة عامة** (تسلسل خطوات، حالات تحميل/خطأ/فارغة، تمييز توصية) — لا كود نُسخ ولا تصميم بصري مستعار: لوحة ألوان Smart Link (oklch مطبخ دافئ بمنطق basil/saffron/ember/espresso موثّق في B) وبنية مكوّناته (FeaturedShowcase، PaymentDialog، PlanComparisonTable) بناء أصلي مستقل عبر 79 جولة. أقرب مرجعين وظيفيًا (QR Menu/MenuQR) LTR إنجليزان بلوحات وأطر مختلفة جذريًا.

## 5) الخلاصة للبوابة

- **ui-ux-pro-max** شُغِّل أولًا وأثبت التوافق (صفر مبادئ High مخالفة).
- **4 مراجع خارجية** دُرست بمصادرها الرسمية؛ كل استلهام موثق بالأعلى بمصدره + كيفية تكيفه لهوية Smart Link تحديدًا.
- **النتيجة الأبرز:** رحلة المرحلة C التي أُغلقت قبل هذه المقارنة كانت قد نفّذت فعليًا أهم ما تُوصي به المراجع (حالات صادقة، feedback دائم، a11y معلن) — المقارنة أكدت الصواب لا قادته.
- **5 فجوات** موثقة لجولات قادمة (FAQ/طاولات/تحليلات مسح/جدولة/تخطيطات) — أُبقيت خارج نطاق round79 التزامًا بنطاق الخطة.
