## 2) المسار المُختبَر فعليًا في كل خلية (16 خطوة موثّقة بلقطة)

`/` (تحقق تطبيق الثيم من localStorage) → `/pricing` → `/subscribe` (اختيار خطة مدفوعة → معالج: بيانات المنيو → بيانات الدخول → مراجعة) → **تسجيل حقيقي** (بعد ركوب حد التردد 5/د) → PaymentDialog (عرض كل التبويبات + إرسال مزود الخلية + ملء الحقول) → حالة الانتظار (استقصاء حقيقي، لا تحققًا تلقائيًا) → **موافقة أدمن عبر API حقيقي** (سياق مستقل + CSRF كامل) → لوحة "تمت الموافقة" → `/owner` → `/owner/menu` (تصنيف جديد + **صنفان مميزان عبر تحكّم المرحلة H**: Switch + ترتيب + شارة، مع التحقق البعدي من الأعلام في القائمة) → `/owner/qr` (توليد QR فعلي من api.qrserver.com + التحقق من تحميل الصورة + إعادة الحجم) → تسجيل خروج (ديسكتوب/موبايل حسب viewport) → `/login` → **دخول حقيقي بالحساب نفسه** → `/owner` → `/menu/[slug]` كعميل نهائي: القسم السينمائي (العنوان "أصنافنا المميزة"، السهمان، النقاط، التالي في الحافة اليسرى RTL، عدّاد sr-only يتغير بالنقر) + **الشبكة الكاملة أسفله سليمة** (الصنفان ظاهران).

## 3) الاحتكاكات الأربع التي اكتشفها التشغيل الفعلي وأُصلحت (بوابة الخطة: أي احتكاك = فشل حتى يُصلح)

### إصلاح 1 — عامل الخدمة PWA كان يخزّن نقاط API المصادَقة (P1، بيانات قديمة بعد POST)
- **العَرَض**: بعد إنشاء تصنيف (POST 201 + توست "تمت الإضافة") كان GET القائمة يُخدَم من نسخة الكاش **ما قبل POST** — التصنيف الجديد يبقى غير مرئي حتى تنقّل لاحق.
- **الجذر**: `public/sw.js` v4 كان يطبّق stale-while-revalidate على **كل** GET `/api/*` (عدا orders/stream) بما فيها نقاط المالك/الجلسة/الدفع.
- **الإصلاح**: قائمة بيضاء `/api/public/*` فقط (قراءة عمومية خالية من الجلسة) + إزالة الدالة الميتة `staleWhileRevalidate` + رفع CACHE_NAME إلى **v5** (إبطال كل كاشات العملاء المنشورة).
- **الدليل**: كل خليات الرحلة الست تظهر "step 10-category-added" متبوعًا فورًا بظهور "مشروبات المرحلة C" في الجسم — الاستقرار اختفى نهائيًا.

### إصلاح 2 — عدّاد ليبيانا الكاذب (P1، احتكاك بصري في حوار الدفع)
- **العَرَض**: شريط تقدم "الإشتراك سينتهي خلال 30 ثانية" يتجمّد عند 30 (المنطق: `autoVerify = false` — العدّاد كان كودًا ميتًا أصلًا) ويوحي بتحقق تلقائي لا يحدث قط (الموافقة يدوية من الأدمن).
- **الإصلاح**: إزالة العدّاد وحالة `countdown` و`deadlineRef` وكتلة `tick` كاملة (−41 سطرًا)؛ الحقيقة الظاهرة = شارة الحالة الصادقة "في انتظار تأكيد الدفع".

### إصلاح 3 — حقل المبلغ البنكي بلا اسم وصول (Critical، اكتشفه axe في الحالة الأغنى)
- **العَرَض**: فحص axe على `/subscribe` **مع حوار الدفع مفتوحًا على تبويب البنك** (حالة لم تُمسح أصلًا في المرحلة B التي مسحت الصفحة مغلقة الحوار) رصد `label/critical`: `<Input type="number" value={bankAmount} min={1}>` — Label مجاور غير مرتبط + لا placeholder ولا aria-label = **لا اسم وصول إطلاقًا**.
- **العَرَض الموضعي**: سكربت التحديد round79-c-label-probe.cjs عاد بالعقدة المستهدفة `#_r_s_` (الحقل بعينه).
- **الإصلاح**: ربط حقول نموذج البنك الثلاثة (المبلغ/اسم المُرسِل/رقم حساب المُرسِل) عبر `useId` + `htmlFor`/`id` — التسمية المرئية نفسها تصبح مصدر الاسم الوصولي الواحد.
- **الدليل البعدي**: نفس السكربت عاد `[]` (صفر انتهاكات) — والرحلة النهائية الكاملة سجّلت **صفر** قواعد axe غير color-contrast عبر الـ48 تشغيلة.

### إصلاح 4 — مفاتيح توفر الأصناف بلا تسمية (a11y، لوحتا الأدمن والمالك)
- مفتاحا Switch في `admin/menu` و`owner/menu` (تغيير توفر الصنف) بلا aria-label — أُضيف `aria-label="تغيير حالة توفر {اسم الصنف}"`.
