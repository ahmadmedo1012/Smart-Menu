## نطاق العمل المنفَّذ (بالأدلة)

### 1) Migration — الحقول الثلاثة على `MenuItem`
- `prisma/migrations/10_add_menu_item_featured/migration.sql` — SQL **idempotent** (`ADD COLUMN IF NOT EXISTS`) لثلاثة أعمدة:
  - `isFeatured BOOLEAN NOT NULL DEFAULT false`
  - `featuredRank INTEGER` (1 = الأول؛ null = بلا ترتيب → الرجوع لترتيب الشبكة)
  - `showcaseTag VARCHAR(40)` (شارة عربية قصيرة مثل "مقرمش")
- **بوابة الخروج مُثبتة**: `npx prisma migrate status` → "11 migrations found… **Database schema is up to date!**" + استعلام `information_schema.columns` يؤكد الأعمدة الثلاثة بأنواعها الصحيحة.
- القاعدة المحلية بُنيت تاريخيًا عبر `db push` (وثّقته المرحلة B) — لذلك سُوّي سجل الهجرات بـ`migrate resolve --applied` لكل الهجرات (0-10) بعد تطبيق SQL الهجرة الجديدة فعليًا عبر `prisma db execute` — وهي طريقة Prisma الرسمية لتبنّي قاعدة قائمة.

### 2) مسار النشر الصفري التعطّل (Zero-downtime) — **إضافة معمارية ضرورية**
اكتُشف أثناء التحليل: دفع `schema.prisma` الجديد يعيد توليد عميل Prisma على Vercel عبر postinstall الخاص بـ`@prisma/client`، وأي استعلام `include` كامل على `MenuItem` (مثل GET `/api/items`) سيتضمن الأعمدة الجديدة → **P2022 على قاعدة الإنتاج غير المتزامنة** = كسر واجهة المالك فور النشر قبل مزامنة يدوية.
- **الحل**: `scripts/round79-db-sync.mjs` — يعمل كأول خطوة في `npm run build` (`package.json`): ينفّذ نفس DDL غير المدمِّر (IF NOT EXISTS) عبر `pg` قبل `next build`. `DATABASE_URL` متاح وقت البناء على Vercel (التوليد الثابت يستعلم القاعدة أصلًا). في كل نشر لاحق: إن كانت الأعمدة موجودة → no-op؛ وإلا تُضاف قبل تقديم الكود الجديد.
- الحماية الذاتية إضافيًا: صفحة المنيو العمومية تستعلم الأعلام عبر **SQL خام محمي** (`.catch(() => [])` عند غياب الأعمدة → لا قسم مميز، دون كسر الصفحة) مع `select` صريح **بدون** الأعمدة الجديدة في استعلام العناصر.
- موثّق للمرحلة F: استبدال هذا بقناة هجرات نظامية.

### 3) واجهة إدارة المالك
- `src/components/owner/ItemDialog.tsx`: قسم جديد "عرض في قسم الأصناف المميزة" — Switch مُعنون + مدخل ترتيب (1-5) + مدخل شارة (40 حرفًا) مع تحقق فوري عربي، والحقول ترسل في نفس جسم PUT/POST.
- `src/app/api/items/route.ts` (POST) و`src/app/api/items/[id]/route.ts` (PUT): مخططات Zod بالحدود نفسها مع رسائل عربية؛ PUT اختياري بالكامل (التحديث الجزئي كتبديل الحالة لا يمس قيم العرض — نفس قاعدة المصفوفات الموثقة).
- `src/app/(protected)/owner/menu/page.tsx`: واجهة `Item` موسعة + **شارة مميز** بجوار اسم الصنف المميز في القائمة.
- **الإثبات (Playwright على بناء الإنتاج المحلي، 11/11 خطوة PASS — `owner-ui-proof.json`)**: دخول → /owner/menu → توسيع تصنيف → فتح حوار تعديل صنف → وجود التحكّم → تشغيله → ظهور مدخلي الترتيب/الشارة → حفظ → **القاعدة: `{isFeatured:true, featuredRank:2, showcaseTag:'محمّص طازة'}`** → الشارة في القائمة → إلغاء التمييز يعيد `{false, null, null}`.

### 4) مكوّن العرض: `src/components/menu/FeaturedShowcase.tsx` (جديد)
- مشهد كامل لكل صنف: الاسم بحجم عملاق كخلفية بتوكِن `text-orange/10`، صورة عبر **OptimizedImage** (إلزامي) بظل درامي، شارة، وصف، سعر (سعر مخفض مشطوب عند وجوده)، سهمان 44px (قانون Fitts من round66)، نقاط موضع، عدّاد حي `sr-only`.
- انتقالات **Framer Motion** (موجودة أصلًا) + `useReducedMotion` يعطّل الانزلاق والعناصر العائمة كليًا (معيار أعلى من الموقع المرجعي).
- أرقام عربية عبر `toArabicNumber`، أسعار بـ"د.ل".
- ألوان **حصريًا من توكِنات المرحلة B** (ember/saffron/orange/border/card/success/muted-foreground) — صفر ألوان خام.

### 5) تدقيق RTL (تصحيحان فعليان أثناء المراجعة قبل الأدلة)
اكتُشف وخُوّل أثناء مراجعة الكود مقابل `GalleryCarousel.tsx` (اصطلاح المشروع):
- **تبديل موضعي الزرين** ليطابقا الاصطلاح القائم: السابق عند الحافة البادئة، **التالي عند الحافة المنتهية (يسار الشاشة في RTL) بسهم يشير يسارًا** = اتجاه التقدم في القراءة RTL — نسخ منطقي معكوس عن الموقع المرجعي LTR كما تفرض الخطة.
- **إصلاح توسيط النقاط**: `start-1/2 -translate-x-1/2` يكسر التوسيط في RTL؛ استُبدل بـ`left-1/2` الفيزيائي (نفس اصطلاح نقاط GalleryCarousel).
- لوحة المفاتيح: `ArrowLeft` = التالي، `ArrowRight` = السابق (معكوس عن LTR عمدًا)، والسهمان زران حقيقيان قابلان للتركيز بحلقات تركيز مرئية.
- الشبكة أدناه + الكرت: `flex-row` منطقي ينعكس تلقائيًا (نص يمينًا/صورة يسارًا) — أكّده فحص VLM البصري.
