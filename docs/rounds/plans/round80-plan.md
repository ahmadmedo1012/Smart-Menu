# Round80 — إغلاق فجوتين مؤكَّدتين من مراجعة Round79 المباشرة

**سياق:** راجعت الكود الحي والموقع المنشور فعليًا بعد Round79. النتيجة: التنفيذ حقيقي (لا هلوسة) لكن فيه فجوتان محددتان بدقة أدناه — هذه الجولة لإغلاقهما فقط، وليست إعادة فحص شامل من الصفر.

**تغيّر مهم عن Round79:** الوكيل الآن **يملك وصولًا فعليًا لـ Vercel** (تعديل متغيرات البيئة/الأسرار مباشرة)، وسيُعطى **صلاحية GitHub الكاملة إن طلبها**. لذلك القسم الأمني في هذه الجولة **قابل للتنفيذ الكامل من الوكيل نفسه** (لم يعد "التزامًا على المالك" كما في Round79) — نفّذه بنفسك من أول خطوة لآخرها، بالترتيب، بلا تخطي.

## المرحلة 1 — تفعيل وتحقق "القسم المميز" فعليًا (أولوية قصوى، نفّذها أولًا)

**الحقيقة المؤكَّدة بالفحص المباشر لبيانات الإنتاج الحية (مطعم `al-waha-cafe`):** كل الأصناف الـ16 لديه `isFeatured: false`. القسم السينمائي (Round79 Stage H) **منشور وموجود في الكود لكن غير مرئي لأي زائر حقيقي حاليًا** لعدم وجود بيانات.

**تأكيد آخر مهم (لتفادي عمل مكرر لا داعي له):** التحكّم الإداري لتفعيل "مميز" **موجود فعلًا** في `src/components/owner/ItemDialog.tsx` و`src/app/(protected)/owner/menu/page.tsx` — **لا تبني UI جديدًا**. المطلوب فقط تحقق أنه يعمل فعليًا من الواجهة الحقيقية + تفعيله على بيانات حقيقية.

**خطوات إلزامية بالترتيب:**
1. سجّل دخول كمالك مطعم `al-waha-cafe` (أو أي مطعم تجريبي حي) من الواجهة الفعلية — لا API مباشر.
2. من `owner/menu`، فعّل خانة "مميز" على 3-5 أصناف فعليًا عبر الزر/الحقل الموجود في `ItemDialog.tsx`، ورتّب أولوياتها إن وُجد حقل ترتيب.
3. أعد تحميل `/menu/al-waha-cafe` كزائر (لا كأدمن) وتأكد أن القسم السينمائي يظهر فعليًا أعلى الصفحة.
4. كرّر الفحص الذي أجريته أنا: اجلب JSON بيانات الصفحة الحية وتأكد أن `isFeatured: true` ظهرت فعلًا لعدد الأصناف التي فعّلتها (لا أقل ولا أكثر).
5. افحص حالة "صفر أصناف مميزة" (edge case): تأكد أن القسم **يختفي بأناقة** لمطعم آخر ما فعّل أي صنف مميز بعد (لا مساحة فارغة، لا خطأ في الكونسول).

**الأدوات الإلزامية:** `gstack /browse` أو Playwright حقيقي (لا فحص API فقط) لالتقاط لقطة الشاشة الفعلية بعد التفعيل + `axe-core` على الصفحة بعد ظهور القسم فعليًا (وليس القياس السابق من Round79 وقت كان القسم فارغًا من البيانات).

**بوابة الخروج (إثبات لا تقرير):**
- استجابة JSON فعلية من الصفحة الحية تُظهر `isFeatured: true` لعدد الأصناف المفعّلة بالضبط.
- لقطة شاشة فعلية للقسم ظاهرًا على `/menu/al-waha-cafe` (Light + Dark).
- لقطة/تأكيد لمطعم آخر بصفر أصناف مميزة يُظهر اختفاء القسم بلا خلل بصري.

## المرحلة 2 — الأمان الكامل (الآن بصلاحياتك الفعلية — نفّذه بنفسك بالكامل)

هذا تصحيح مباشر لواقعة Round79: تحويل المستودع لخاص قبل تدوير الأسرار وإعادة تفويض Vercel عطّل النشر. **الترتيب أدناه إلزامي وغير قابل لإعادة الترتيب.**

### 2.1 تدوير أسرار Vercel أولًا (لديك الوصول الآن)
- ادخل Vercel Dashboard → Project → Settings → Environment Variables.
- ولّد قيمًا عشوائية جديدة (64 hex) لـ `JWT_SECRET` و`AUTH_SECRET`.
- إن استُخدم `TELEGRAM_BOT_TOKEN` مؤخرًا: دوّره من BotFather.
- دوّر `CRON_SECRET`.
- دوّر كلمة مرور قاعدة Neon (`DATABASE_URL`) من لوحة Neon، وحدّث المتغير في Vercel.
- بعد كل تحديث: Redeploy فعلي (ليس حفظًا فقط) — تدوير `JWT_SECRET`/`AUTH_SECRET` يُبطل كل الجلسات القائمة، وهذا **سلوك متوقّع وصحيح**، لا خطأ.

**بوابة:** استجابة فعلية من `/api/auth/login` بعد إعادة النشر تُثبت أن النظام يعمل بالسر الجديد (تسجيل دخول ناجح باستخدام حساب اختبار).

### 2.2 إعادة تفويض تكامل Vercel↔GitHub *قبل* التحويل لخاص
- Vercel → Project Settings → Git → تأكد أن تطبيق Vercel GitHub لديه صلاحية "Repository access" صريحة تشمل `Smart-Menu` (لا "All repositories" تلقائي فقط — تحقق أنها ستبقى فعّالة بعد التحويل لخاص).
- إن لم تكن موثّقة: أعد التفويض من GitHub → Settings → Applications → Installed GitHub Apps → Vercel → Configure → أضف `Smart-Menu` صراحة ضمن مستودعات الوصول.

**بوابة:** لقطة شاشة فعلية من إعدادات GitHub App تُظهر `Smart-Menu` ضمن قائمة المستودعات المصرَّح بها لتطبيق Vercel.

### 2.3 تحويل المستودع لخاص — الآن فقط
```
PATCH api.github.com/repos/ahmadmedo1012/Smart-Menu {"private":true}
```
ثم فورًا: ادفع كوميت فارغ تجريبي (`git commit --allow-empty -m "test: verify deploy while private"`) وراقب Vercel Deployments حتى ينجح النشر **وهو خاص** — لا تعتبر هذه الخطوة منتهية إلا بعد نشر ناجح واحد فعلي بعد التحويل.

**بوابة (الأهم في هذه الجولة كلها):** رابط نشر Vercel فعلي حالته `Ready` مع طابع زمني بعد التحويل لخاص + استجابة `PATCH` الأصلية تُظهر `"private": true`.

### 2.4 إبطال التوكن المؤقت + تنظيف الأثر الموثَّق
- أبطل توكن GitHub المؤقت المذكور جزئيًا في `docs/round79-phaseF-security.md` (`ghp_0U3xOtAd…`) من GitHub → Settings → Developer settings → Personal access tokens **فورًا** بغض النظر عن هذه الجولة.
- إن كان لديك صلاحية الآن: أنشئ توكنًا جديدًا محدود الصلاحيات (Fine-grained، هذا المستودع فقط، Contents: Read/Write) بدل التوكن العام القديم، واستخدمه من الآن فصاعدًا.

**بوابة:** استجابة GitHub تؤكد إبطال التوكن القديم (403 عند محاولة استخدامه) + تأكيد أن التوكن الجديد (إن وُجد) محدود النطاق فعلًا (فحص Fine-grained permissions من صفحة التوكن).

## المرحلة 3 — إغلاق قائمة متابعة Round79 (غير حاجبة لكنها مطلوبة هذه الجولة)

من `docs/round79-launch-readiness.md` §4، بالترتيب حسب الخطورة الفعلية:

1. **استبدال `scripts/round79-db-sync.mjs` بقناة migrations نظامية**: تأكد أن `vercel.json` أو `buildCommand` يشغّل `prisma migrate deploy` بدل سكربت مخصص، وتحقق مرة واحدة من `information_schema` على قاعدة الإنتاج أن كل الجداول متزامنة مع `schema.prisma`.
2. **تصليب بوابة اختبار لوحة المفاتيح** في `tests/e2e/round79-phaseC-journey.spec.ts`: تأكد أن التركيز يُضبط على عنصر قابل للتركيز فعليًا قبل الضغط، لا افتراضًا.
3. **تحديث `AXE_BASELINE`** بالعدد الحقيقي الحالي للعقد بعد ظهور القسم المميز فعليًا (المرحلة 1 أعلاه تغيّر DOM الصفحة)، وأضف حارسًا يفشل البناء لو زاد عدد انتهاكات axe عن الأساس الجديد دون مبرر موثَّق.
4. **توحيد دلالة لون "التوفير/الخصم"** بين `FeaturedShowcase.tsx` وبطاقة السعر العادية بقرار تصميمي واحد (لا تتركهما بلونين مختلفين لنفس المعنى).
5. **تغطية اختبارات مفقودة**: مسار رفض الدفع كاملًا، إخفاء القسم عند صفر أصناف مميزة (مرتبط بالمرحلة 1 فوق)، حدود `lib/validation.ts` كوحدات منفصلة.

**بوابة كل بند:** ناتج `npm run typecheck && npm run lint && npm run test && npm run build` = صفر أخطاء بعد كل بند، لا دفعة واحدة في النهاية.
